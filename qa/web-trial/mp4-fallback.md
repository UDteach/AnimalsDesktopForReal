# iPhone向けMP4フォールバック

2026-09-27。基準コミット `3b07b6e`。

ユーザー報告: iPhoneのSafariとChromeではトップページの動画は動くが、おためし画面に「動画を再生できない」と表示される。
トップは既存MP4へ切り替える一方、おためしは透過WebMから直接PNGに切り替えていた。
Playwright WebKit 26.6のiPhoneモードで、修正前に同じPNGへの切り替えと文言を再現した。

修正: おためしが明示的に許可した場合だけWebM → 同じ動物・動作のMP4 → PNGへ切り替える。全64本の既存MP4を使う。MP4中はデコードしたフレームの隅の色に背景を合わせ、背景選択を停止する。PNG/WebMに戻ったら保存済みの背景へ復帰する。OBSはMP4を許可せず従来の透明PNGへ切り替える。

確認済み:

- WebKitのiPhoneモードでMP4の `currentTime` が進み、再生中に失敗の案内が出ない。
- 一時停止・再開、ページ内拡大と復帰、横スクロールがないこと。背景の微妙な色差は、固定CSS色から実際のデコード色を読む方式へ修正して再撮影した。
- WebKitでMP4を404にするとPNG、解除すると再びMP4が再生される。
- ChromiumのWebM再生、WebMの404でMP4、両方404でPNG。同じ動物のまま切り替わり、PNGでは背景選択が戻る。
- 新規ブラウザコンテキストで全素材404にすると読み込み失敗の案内が出る。既にデコード済みのPNGは通信障害注入後も再利用されたため、この検証は新規コンテキストで実施した。
- OBSプレビューはWebMの404でPNGへ切り替わり、MP4へのリクエストは0件。復旧後のWebM再生も確認。
- `npm run check:obs` 8テスト、`npm run check` 12テストと素材検査、JavaScript構文検査、生成物の一致、`git diff --check` が合格。
- Safariが旧モジュールを再利用するケースを確認したため、新しい入口と依存モジュールに版を示すクエリを追加した。

証跡: [WebKitのiPhoneモード](mp4-webkit.png)。このMacにはiOS Simulatorのランタイムがなく、iPhone実機・iOS Simulatorでの検証は未実施。WebKitの確認と実機の確認を同一とは扱わない。

参考: [WebKitのVP9透過表示に関する報告](https://bugs.webkit.org/show_bug.cgi?id=275908)。今回の原因判断はこれに加え、既存トップのMP4分岐と修正前のおためしの再現結果を根拠にしている。
